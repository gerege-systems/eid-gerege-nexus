# eID Mongolia

Энэ суулгацын нэвтрэлт, гарын үсэг хоёр бүхэлдээ **eID Mongolia**-д тулгуурладаг.
Энэ файл нь тэр рэйлийг нэг дор бичсэн лавлах: юу вэ, ямар утга нь юуг
хэлдэг, энэ платформ түүнтэй яг хаанаас нь ярьдаг вэ.

Эх сурвалж: [eidmongolia.mn](https://eidmongolia.mn) (нийтийн танилцуулга,
`/api/integration` дээрх RP-ийн заавар), болон энэ платформын кодод буй
хэрэгжилт — цөмийн `backend/internal/kernel/eidrp` (нэвтрэлт),
`kernel/eidsign` (гарын үсэг), `workspace/identity/eidmongolia` (суулгацад
тааруулах давхарга).

---

## 1. Юу вэ

Монгол Улсын **үндэсний цахим үнэмлэх** ба лицензтэй **гэрчилгээжүүлэх төв
(CA)**, Gerege Systems ХХК ажиллуулдаг. Иргэн утсандаа нэг апп суулгаснаар
нэвтэрч, гарын үсэг зурж, өөрийн гэрчилгээ, төхөөрөмжөө удирдана.

Архитектур нь Эстонийн **Smart-ID**-тэй нийцтэй: түлхүүр нь утсанд бүтнээрээ
байдаггүй, threshold ECDSA-аар хуваагдсан байдаг тул хулгайлагдсан утас
дангаараа гарын үсэг зурж чадахгүй. Түлхүүрийн серверийн тал нь **FIPS 140-2
Level 3** HSM-д, тэндээсээ гардаггүй.

Нийтэлсэн тоо, гэрчилгээ: 1.2 сая гаруй идэвхтэй хэрэглэгч, 2.4 сая гэрчилгээ,
ISO/IEC 27001, GDPR, «Цахим гарын үсгийн тухай хууль»-ийн дагуу, EU eIDAS-ийн
QES-тэй уялдуулсан. SOC 2 Type II нь явцад.

### Ямар үйлчилгээ үзүүлдэг вэ

| Үйлчилгээ | Иргэнд | Энэ платформд |
|---|---|---|
| **Танилт** | PIN1-ээр нэвтрэх | `authentication/*` — QR, push, App2App |
| **Гарын үсэг** | PIN2-оор баримт баталгаажуулах | `signature/*` — QES, PAdES-T |
| **Гэрчилгээ** | эзэмших, түвшин, хүчинтэй хугацаа | `signature/certificate/{documentNumber}` |
| **Төлөөлөл** | аль байгууллагыг төлөөлж болохоо харах | `organization/representations/*` |
| **Итгэлцэл** | гарын үсгээ гуравдагч талд шалгуулах | OCSP, CRL, Adobe AATL (§8) |
| **RP хөтөлбөр** | — | UUID + `rp_sk_…`, `AUTH`/`SIGN`/`CERT` (§9) |

Иргэний тал бүхэлдээ утсан дээрх нэг аппад: бүртгэл, ПИН солих, PUK-аар
сэргээх, төхөөрөмжөө удирдах. Энэ платформ тэдгээрийн аль нэгийг нь ч
давхардуулдаггүй — үнэмлэхийг эзэн нь өөрөө барина, бид зөвхөн асууна. Тиймээс
нууц үг сэргээх урсгал, ПИН солих дэлгэц энд БАЙХГҮЙ нь дутуу байгаа хэрэг
биш.

## 2. Хоёр ПИН ба нэг код

Гурвыг андуурах нь энэ рэйл дээрх хамгийн түгээмэл алдаа, тиймээс эхэнд:

| Юу | Урт | Хаана | Юунд |
|---|---|---|---|
| **PIN1** | 4 орон | утсан дээр | **танилт** — нэвтрэх, лавлагаа авах |
| **PIN2** | 4 орон | утсан дээр | **гарын үсэг** — хуулийн хүчин төгөлдөр үйлдэл |
| **Баталгаажуулах код (VC)** | 5 орон | дэлгэц БА утас дээр зэрэг | зөвхөн НҮДЭЭР тулгах |
| **PUK** | — | бүртгэлийн үед өгсөн | мартсан ПИН сэргээх |

VC бол **ПИН биш**. Түүнийг хаана ч бичдэггүй: вэб дээр гарсан таван орон,
утсан дээр гарсан таван орон хоёр таарч байвал иргэн зөв session-ыг
зөвшөөрч байна гэсэн үг. Урт нь өөр байгаа нь санаатай — 4 ба 5.

PUK-аа ч мартвал дахин бүртгүүлэхээс өөр зам байхгүй.

**Регистрийн дугаар** — иргэний үнэмлэхний ар талд, кирилл 2 үсэг + 8
цифр (жишээ: `МА74101813`).

## 3. Таних тэмдэг — ETSI EN 319 412-1

eID хүн, байгууллага хоёрыг стандарт семантик тэмдгээр түлхүүрлэнэ:

```
PNOMN-<регистрийн дугаар>     иргэн   (natural person, MN)
NTRMN-<улсын бүртгэлийн дугаар>  байгууллага (legal entity, MN)
```

Код дотор `eidmongolia.PersonEtsi()` ба `OrgEtsi()` — угтвар нь аль хэдийн
байвал давхарлахгүй.

## 4. v3 протокол

Суурь хаяг **`https://eidmongolia.mn/v3`**. Гарын үсгийн зарим endpoint нь
`/v3`-гүй язгуураас эхэлдэг тул код нь суурийг хоёуланг нь барьдаг
(`EID_SIGN_BASE_URL` → `V3BaseURL` нь `/v3`-г тайрдаг).

### Толгойнууд

```
Authorization: Bearer rp_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json
```

Итгэмжлэл буруу бол `401`. IP allowlist тохируулсан байхад жагсаалтад
байхгүй хаягаас ирвэл `403`.

### Энэ платформын дуудлагууд

| Дуудлага | Юу |
|---|---|
| `POST /authentication/device-link/anonymous` | QR нэвтрэлт (хөндлөн төхөөрөмж) |
| `POST /authentication/notification/etsi/PNOMN-{РД}` | push нэвтрэлт регистрээр |
| `POST /signature/notification/etsi/{иргэн}` | PIN2 гарын үсгийн ceremony |
| `POST /signature/certificate/{documentNumber}` | гэрчилгээ татах |
| `GET  /session/{sessionID}?timeoutMs=25000` | long-poll |
| `GET  /organization/representations/etsi/{personEtsi}` | төлөөлж болох байгууллагууд |

### Нэвтрэлтийн их бие (ACSP_V2)

```json
{
  "relyingPartyUUID":  "…",
  "relyingPartyName":  "eID Gerege",
  "certificateLevel":  "ADVANCED",
  "signatureProtocol": "ACSP_V2",
  "rpChallenge":       "<санамсаргүй, base64>",
  "interactions":      [{"type":"displayTextAndPIN","displayText60":"eID Gerege-д нэвтрэх"}],
  "initialCallbackUrl":"https://eid.gerege.mn/auth/eid/callback"
}
```

Гурван зүйл дээр бүдэрдэг:

- **`rpChallenge` нь нэвтрэлтийнх**, гарын үсэг нь `digest`/`hashType`.
  Сольж илгээвэл сервер дээр challenge хоосон үлдэж, иргэн апп дотроо
  зөвшөөрөх мөчид «боловсруулах» алдаа хардаг — өөрийнх нь буруу мэт.
- **`displayText60` нь 60 ТЭМДЭГТ**. Бичвэр нь монгол тул үсгээр (rune)
  тоолж таслах ёстой; байтаар таславал үг дундуур тасарна.
- **`initialCallbackUrl` хоосон = хөндлөн төхөөрөмж.** Утсыг хаашаа ч
  буцаахгүй, браузер өөрөө поллдоно. Утас дээрх App2App-д л заана.

Хариу:

```json
{"sessionID":"…","vc":{"type":"alphaNumeric5","value":"12345"}}
```

QR-д шифрлэх зүйл нь **дан session id**, device-link URL БИШ: eID-ийн
сканнер UUID уншаад өөрийн сервер рүүгээ шийддэг.

### Session-ы төлөв

eID нь `RUNNING` эсвэл `COMPLETE` гэж хариулна — `COMPLETE` нь зөвхөн
«дууслаа» гэсэн үг. Бодит үр дүн нь `result.endResult` дотор:

```json
{"state":"COMPLETE",
 "result":{"endResult":"OK","documentNumber":"…"},
 "signature":{"value":"MEQCI…","signatureAlgorithm":"ecdsa-with-SHA256"},
 "cert":{"value":"MIID…","certificateLevel":"ADVANCED"}}
```

Платформ дээшээ дөрвөн төлөв гаргана: `COMPLETE`, `EXPIRED`, `REFUSED`,
`RUNNING`.

### Иргэний блок

Гурван нэр нь гурван өөр зүйл бөгөөд eID үүнийг санаатай ялгадаг:

| Талбар | Монголоор | Тэмдэглэл |
|---|---|---|
| `firstName` | нэр | |
| `lastName` | **эцгийн нэр** | гэрчилгээнд байдаг цорын ганц нь |
| `familyName` | ургийн овог | гэрчилгээнд БАЙХГҮЙ |
| `firstNameEn`, `lastNameEn` | ICAO том үсгээр | латин ургийн овог гэж байхгүй |
| `birthDate` | `YYYY-MM-DD` | цаг, бүсгүй |
| `gender` | `M` / `F` / `X` | |
| `geID` | Gerege бүртгэл дэх дугаар | тулгагдаагүй иргэнд байхгүй — шаардаж БОЛОХГҮЙ |
| `kycLevel`, `documentNumber` | | |

`lastName`-ийг family name гэж үзсэн код англиар зөв уншигдаж, монгол хүнд
илт буруу харагдана.

## 5. Гэрчилгээний түвшин

```
ADVANCED    нэвтрэлтэд   — иргэдийн ИХЭНХ нь энэ түвшинтэй
QUALIFIED   гарын үсэгт  — QES; үүнээс доош нь хуулийн хүчингүй
```

Хоёрыг тусад нь тавьсан нь санаатай. Нэвтрэлтэд QUALIFIED шаардвал ихэнх
иргэнийг хаана, тэдний харах алдаа нь «сервер лүү холбогдож чадсангүй» гэсэн
гэрчилгээний тухай юу ч хэлдэггүй мессеж болно. Харин гарын үсэг ADVANCED
хүлээж авбал QES биш зүйлийг чимээгүйхэн QES мэт үйлдвэрлэнэ.

Тохиргоо: `EID_CERT_LEVEL=ADVANCED` (нэвтрэлт), `EID_SIGN_CERT_LEVEL=QUALIFIED`
(гарын үсэг, анхдагч).

## 6. Гарын үсгийн ceremony

1. Иргэн PDF өгнө. Сервер нь гарын үсгийн зураг, байгууллагын тамгыг
   сүүлийн хуудсанд **хэшлэхээс ӨМНӨ** давхарлана — тэгснээр хоёул гарын
   үсэг зурагдсан зүйлийн нэг хэсэг болно.
2. SHA-256 нь eID рүү явна. **Файл өөрөө хэзээ ч явахгүй.**
3. eID иргэний утас руу PIN2 асуулт түлхэнэ. Иргэний зөвшөөрөл нь хуулийн
   зөвшөөрөл — тэр агшин.
4. Сервер session-ыг терминал болтол нь поллдоно.
5. Татахад eID-ийн өөрийн stamp endpoint нь **PAdES-T** гаргана: RFC 3161
   цагийн тамга + `eidmongolia.mn/verify` дээрх нийтийн шалгах хуудас. Тэр
   endpoint унасан үед сервер өөрийн **Document-Signer** гэрчилгээгээр
   PAdES шигтгэнэ.

Document-Signer байхгүй суулгац гарын үсэг зурсаар байна — зөвхөн нөөц замаа
алдана, түүнийг нь татах үед алдаа болгож хэлдэг, ачаалах үед биш.

Хязгаар: PDF нь 1 байтаас 25 MB хүртэл; дан дижест нь 64 тэмдэгт hex SHA-256.

### Байгууллагын нэрийн өмнөөс

`onBehalfOf = NTRMN-<регистр>` нь **хэний түлхүүр гарын үсэг зурахыг
өөрчилдөггүй** — иргэний PIN2 гэрчилгээ хэвээр. Нэмэгдэх зүйл нь: session
нээгдэх үед eID төлөөлөх эрхийг улсын бүртгэлээс шалгана, батлагдсан
байгууллагын нэр гарын үсгийн `reason`-д бичигдэнэ. Энэ нь **төлөөллийн
бичилт, тамга биш**.

### Session-ы эзэмшил

Poll ба download хоёр нь ceremony эхлүүлсэн регистрийн дугаар дээр
шалгагдана: нэг иргэн нөгөөгийнхөө session-ыг id таамаглаж уншиж чадахгүй.
Байхгүй session ба өөр хүний session хоёрт **ижил** хариу очно — байгаа
эсэхийг нь оролдож мэдэх боломжгүй.

## 7. Төлөөлөх эрх

`GET /organization/representations/etsi/PNOMN-{РД}` нь тухайн иргэний
одоогийн байдлаар төлөөлж болох байгууллагуудыг буцаана: `orgEtsi`,
`orgRegister`, `orgName`, `orgNameEn`, `role`, `rightType` (`ADMIN` |
`MANAGER`), `validFrom`, `validTo` (`null` = нээлттэй).

Эрхийг **гэрчилгээнээс биш, бүртгэлээс амьдаар** уншдаг: өчигдөр огцорсон
захирал өчигдрийн гэрчилгээгээ барьсан хэвээр байдаг.

## 8. Итгэлцлийн үйлчилгээ

| Юу | Хаяг |
|---|---|
| OCSP — гэрчилгээ хүчинтэй эсэх | `https://eidmongolia.mn/verify` |
| CRL — хүчингүй болсны жагсаалт | `https://crl.eidmongolia.mn` |
| Adobe AATL итгэмжлэл | `https://eidmongolia.mn/trust/adobe` |

X.509, түлхүүр нь HSM-ээс гардаггүй, амрах өгөгдөл AES-256. Гуравдагч тал
энэ платформоос юу ч асуухгүйгээр гарын үсгийг шалгаж чадна — PAdES-T
файлыг Adobe Reader дангаар нь хүлээн зөвшөөрдөг нь тэр учраас.

## 9. Relying party болох

Өргөдөл: [eidmongolia.mn/rp-apply](https://eidmongolia.mn/rp-apply), эсвэл
`POST /v3/rp-applications` (хариу нь `PENDING` — операторын баталгаа хүлээнэ).

Бөглөх зүйл:

- байгууллагын нэр — **иргэн утсан дээрээ яг үүнийг уншина**
- улсын бүртгэлийн дугаар, холбоо барих хүн, и-мэйл (шийдвэр, secret энд ирнэ)
- зорилго: **`AUTH`** (нэвтрэлт) · **`SIGN`** (гарын үсэг) · **`CERT`** (гэрчилгээ)
- App2App-ийн буцах домэйн (сонголтоор, таслалаар)
- mTLS клиент гэрчилгээний subject DN (сонголтоор, дараа ч нэмж болно)

Батлагдвал **UUID** ба **`rp_sk_…` secret** олгоно. Secret нь **ганцхан удаа**
харагдана, зөвхөн backend-д хадгална. Нэг бүртгэл AUTH ба SIGN хоёуланг
барьж чадна — энэ суулгац яг тэгж ашигладаг.

Зөвлөмж: production-д IP allowlist, боломжтой бол mTLS.

## 10. Энэ суулгац хэрхэн холбогддог

`.env` (`deploy/docker-compose.yml` дамжуулна):

| Хувьсагч | Юу |
|---|---|
| `EID_RP_UUID`, `EID_RP_SECRET` | RP итгэмжлэл. Хоосон бол **хэн ч нэвтэрч чадахгүй** |
| `EID_RP_NAME` | иргэний уншдаг нэр — `eID Gerege` |
| `EID_DISPLAY_TEXT` | ПИН-ийн дээр гарах бичвэр, 60 үсэг |
| `EID_BASE_URL` | `https://eidmongolia.mn/v3` |
| `EID_CERT_LEVEL` | `ADVANCED` — нэвтрэлтийн доод хязгаар |
| `EID_MOCK_MODE` | хийсвэр session; production-д `false` |
| `EID_SIGN_CERT_LEVEL` | `QUALIFIED` (анхдагч) |
| `EID_SIGN_DISPLAY_TEXT` | PIN2-ын дээрх бичвэр |
| `EID_SIGN_SIGNER_CERT_PEM` / `_FILE` | Document-Signer гэрчилгээ (нөөц зам) |
| `EID_SIGN_SIGNER_KEY_PEM` / `_FILE` | түүний ECDSA хувийн түлхүүр |

eID дээр бүртгүүлсэн callback нь **яг** `${PUBLIC_ORIGIN}/auth/eid/callback`
байх ёстой. App2App-ийн буцах домэйнууд нь `DEVICE_LINE_ORIGINS` ба
`OAUTH_REDIRECT_HOSTS` хоёуланд байх ёстой — сүүлийнхэд байхгүй host руу
буцах redirect бүр татгалзагдана.

Поллын цонх нь 20 секунд (`eidmongolia.PollWindow`), eID-ийн барьдаг 25
секундээс доогуур бөгөөд API-ийн бичих deadline-аас доогуур: дээгүүр
гарсан хүсэлт хариугүй хаагдаж, иргэн proxy-ийн алдааны хуудас хардаг.

`nginx/snippets/eid-api-proxy.conf` нь `eidmongolia.mn` руу шууд proxy хийдэг
— native клиент болон вэб хоёр ижил origin дээр үлдэх нь энэ.

## 11. Ширээний клиент ба USB токен

`native-apps/desktop/` дэх macOS, Windows клиентүүд нь **first-party клиент**:
RP secret, device HMAC, урт насладаг bearer token **аль нь ч байхгүй**.
Бүх дуудлага нь вэбтэй яг ижил нийтийн `/api/*` замуудаар явна, RP secret нь
серверт үлдэнэ.

Тэдгээрийн нэмдэг зүйл нь **USB крипто токен**: `gerege-token-kit` (PKCS#11)
нь токен дээр түлхүүр үүсгэж, CSR илгээж, PSO гарын үсэг зурна. ДАН/isf.mn
рүү нэвтрэх «Тоон гарын үсэг (клиент програм)» гүүр нь
`ws://127.0.0.1:59001` дээр сууж, браузераас ирсэн байт дээр гарын үсэг зураад
серверийн гэрчилгээгээр битүүмжилж буцаадаг
(`native-apps/desktop/macos/ESIGN-DAN-PROTOCOL.md`).

Утсан дээр нэвтрэлт нь App2App: eID Mongolia апп руу үсэрч зөвшөөрнө.

### Аль RP-ээр нэвтэрдэг вэ

Энэ нь тааруулга биш, иргэний харах НЭР: session эхлүүлсэн RP-ийн нэрийг eID
апп зөвшөөрөл асуухдаа дэлгэцэн дээрээ бичнэ.

`nginx/eid.gerege.mn.conf` дээр `/api/(start|status|login-notify|…)` бүлэг нь
**eidmongolia.mn** руу proxy хийгддэг — тэдгээр нь eID Mongolia-гийн ӨӨРИЙН
вэб аппын route-ууд бөгөөд session нь ТЭДНИЙ demo RP-ээр үүсдэг. Тиймээс
эдгээрээр нэвтэрсэн иргэн утсан дээрээ «RP Demo Bank» гэж уншдаг байв — өөр
бүтээгдэхүүн зөвшөөрүүлж байгаа мэт.

Хөтөч тэгдэггүй: вэб нь платформын өөрийн `/api/v1/auth/eid/{start,start-id,poll}`
руу явдаг тул `EID_RP_NAME` буюу **eID Gerege** харагдана.

**Дөрвүүлэн (macOS, Windows, iOS, Android) одоо хөтөчийн замаар явна.**
Дагалдах зүйлс:

- `callbackUrl` нь ХООСОН. Платформ нь `${PUBLIC_ORIGIN}/auth/eid/callback`-аас
  өөр хаягийг хүлээж авдаггүй (цөмийн `validEIDCallback`) тул гуравдагч схем
  (`gerege-eid://auth`) 400 өгнө. eID апп зөвшөөрснийхөө дараа биднийг өөрөө
  нээхгүй — хүн гараараа буцаж ирнэ, ажиллаж буй poll нэвтрэлтийг дуусгана.
  Автомат буцалт сэргэхийн тулд цөм нь `DEVICE_LINE_ORIGINS`-д бүртгэсэн
  схемийг зөвшөөрөх ёстой.
- Poll нь 25 секунд барина (`eid.PollWindow`) тул клиентийн хүсэлтийн timeout
  түүнээс ДЭЭГҮҮР байх ёстой — iOS/macOS дээр 60с, Windows дээр
  `RequestTimeoutSeconds: 60`.
- eID вэб аппын нэмэлт өгөгдөл (`/api/dashboard`, `/api/representations`,
  `/api/children`, `/api/certificates`) нь ТЭР аппын `pollToken`-оор л
  уншигддаг тул утсан дээр цаашид татагдахгүй. Нэр нь платформын
  `identity`-гээс МОНГОЛООР ирдэг тул нэвтрэлтэд хэрэггүй болсон; байгууллага,
  хүүхдийн жагсаалт хоосон үлдэнэ.

**Ширээн дээр юу алдагдсан бэ.** eID вэб аппын `pollToken` нь ЗӨВХӨН тэр
аппын нэвтрэлтээс гардаг тул түүнд түшсэн зүйлс шинэ нэвтрэлтээр шинэчлэгдэхээ
болино:

| Юу | Төлөв |
|---|---|
| PDF гарын үсэг (`/api/sign-pdf-*`) | **АЖИЛЛАНА** — өөрийн session-ыг `etsi`-ээр эхлүүлдэг |
| ESIGN/ДАН гүүр | Keychain-д кэшлэгдсэн гэрчилгээ байвал ажиллана; шинээр татагдахгүй |
| Байгууллага, хүүхэд, XYP-ийн хураангуй | хоосон |

Гэрчилгээ (`/api/certificates`) нь session-bound тул платформ дээр дүйцэх
endpoint гартал ESIGN шинэ гэрчилгээ авахгүй. Дараалал нь: цөмд гэрчилгээний
route нэмэх → энд дахин холбох. Худал өгөгдөл харуулахын оронд хоосон
үлдээсэн нь санаатай.

## 13. Энэ суулгац юугаараа хүчтэй вэ

eID нь хэн болохыг хэлээд зогсоно. Түүнээс хойших бүхэн энэ суулгацынх —
нүүр хуудсанд тоочих эрхтэй зүйл нь ч яг тэр:

- **Цөмийг fork хийдэггүй.** Хуудасны аргумент нь `LANDING_SECTIONS`, үг нь
  `brand/copy.json`. Өөр байр суурь илэрхийлэхийн тулд код биш тохиргоо
  солино — тиймээс цөмийн аюулгүйн засвар энд Dependabot-ийн нэг PR болж
  ирдэг, хоёр дахь платформ болж хуваагддаггүй.
- **Дөрвөн native клиент, нэг API.** macOS, Windows, iOS, Android бүгд
  вэбтэй ЯГ ижил нийтийн `/api/*` замаар явна; RP secret серверт үлдэнэ
  (§11). Ширээнийх нь дээрээс USB крипто токен ба ДАН/isf.mn-ийн гүүр нэмнэ.
- **Нэг origin.** `nginx/snippets/eid-api-proxy.conf` нь `eidmongolia.mn` руу
  proxy хийдэг тул вэб ба native клиент хоёр CORS, гуравдагч cookie-гүйгээр
  ижил хаягнаас ярина.
- **Ажиглалт нь суурь, нэмэлт биш.** Prometheus, Alertmanager, Loki, Tempo,
  Alloy, Grafana ба SLO дүрмүүд
  (`deploy/monitoring/prometheus/rules/`), алдааны урсгал GlitchTip-д.
  Хэмжигдээгүй зүйл чимээгүй эвдэрдэг.
- **Нөөцлөлт өдөр бүр 03:15-д** (`deploy/scripts/backup.sh`): хостыг
  орхихоосоо ӨМНӨ шифрлэгдэж, эх сервер нь түүхээ устгаж чадахгүй сан руу
  очно.
- **Тусгаарлалт өгөгдлийн санд.** Session токен хэшээр хадгалагдана,
  тенантын хүсэлт database role, tenant context, RLS-ээр тусгаарлагдана, eID
  ceremony бүр эзэнтэй (§6).
- **Долоон хэл**, дутсан орчуулга англи руу fallback хийнэ — монгол иргэн ба
  гадаад аудит хоёр нэг хуудас уншина.
- **CI бүрэн:** push бүрд образ барина, долоо хоног тутам эмзэг байдал
  сканердана (`.github/workflows/`), rollout нь `deploy.sh` — татаж, барьж,
  сольж, шалгана.

Эдгээрийн аль нь ч eID-ийн гавьяа биш, мөн эсрэгээрээ: eID-гүйгээр эдгээр нь
нууц үгтэй платформын онцлог болж хямддаг.

## 14. Нүүр хуудас

Нүүр хуудсанд юу бичигдэхийг `brand/copy.json` шийднэ (`BRAND_COPY_FILE`),
дарааллыг нь `LANDING_SECTIONS`. Одоогийн дараалал ба тэдгээр нь энэ баримтын
хаанаас гаралтай нь:

| Хэсэг | Юу хэлдэг | Эх нь |
|---|---|---|
| `hero` | нууц үг биш, eID | §1 |
| `capabilities` | PIN1, PIN2, төлөөлөл, VC | §2, §6, §7 |
| `trust` | гэрчилгээнээс эрх хүртэлх гинж | §5, §6, §8 |
| `services` | eID ба хажууд нь юу ажиллаж байна | §1, §13 |
| `architecture` | хаалганы цаана ямар платформ байна | §13 |
| `platform` | асаалттай байгаа зүйлс | §13 |
| `technology` | Nexus → eID → OIDC гурван карт | §4 |

`applications` жагсаалтад БАЙХГҮЙ нь санаатай: энэ репо өөрийн модульгүй тул
тэр хэсэг цөмийн ганц бүртгэлийн аппыг жагсаах байв. Хэсгийг орхиход цэсний
мөр нь ч хамт явна — хаашаа ч хүргэхгүй холбоос үлдэхгүй.

Тоо, нэр өөрчлөгдвөл энэ баримт ба `copy.json` ХОЁУЛАНГ нь засна. Цөмд
ar/es/fr/ru/zh overlay-тэй түлхүүрийг долоон хэлээр бүтнээр нь бичих ёстой —
шалтгаан ба шалгах арга нь `brand/README.md`-д.
